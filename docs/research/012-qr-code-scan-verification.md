# QR Code 產生器實機掃描驗證

Issue：#131。版本識別碼：`qr-code-scan-2026-11`。這份紀錄確認 QR Code 產生器產出的碼，能被台灣使用者手上常見的手機內建相機正確讀取。**目前狀態：待執行**，發布到 production 前必須完成並把結果填入第 4 節。

## 1. 為什麼需要實機掃描

自動測試已證明兩件事：工具組出的文字符合預期（`tests/qr-code-domain.test.ts` 的 Wi-Fi 跳脫、網址補前綴與容量上限），以及把碼畫成 PNG 實際使用的像素後，`jsqr` 能逐字解回原文。

自動測試證明不了的是手機相機怎麼「理解」解出來的文字：會不會把網址當成連結打開、會不會詢問加入 Wi-Fi、名稱與密碼裡的符號會不會被正確還原、十六進位樣子的網路名稱加上雙引號後是否仍連得上。這些只能用實體手機確認。

## 2. 準備

- 從 develop 的 preview 或本機 `npm run build && npm run preview` 開啟 `/zh-tw/tools/qr-code-generator/`，依第 3 節逐項產生並下載 PNG 與 SVG。
- 每一項各準備兩種載體：螢幕顯示（另一台裝置全螢幕開啟 PNG），以及印在 A4 紙上、邊長約 3 公分的列印版（SVG）。
- Wi-Fi 項目需要可以自行設定的路由器或手機熱點；「只支援 WPA3」一項需要能關閉 WPA2 相容模式的設備。
- 測試裝置至少一支 iPhone（iOS 內建相機）與一支 Android（內建相機或系統掃描器），記下機型與系統版本。

## 3. 測試項目

| 編號 | 內容類型 | 輸入 | 預期結果 |
| --- | --- | --- | --- |
| S1 | 網址 | `line.me/R/ti/p/@` 加上一個實際存在的 LINE 官方帳號 ID | 相機提示開啟 `https://line.me/...`，點下後進入該帳號 |
| S2 | 網址 | 一個 Google 地圖分享連結 | 相機提示開啟地圖連結 |
| S3 | 文字 | `歡迎光臨！週一公休\n其餘 11:00 開門`（含換行） | 顯示完整文字，中文不亂碼、換行保留 |
| S4 | Wi-Fi | 名稱 `測試 Wi-Fi`、密碼 8 個字元以上，加密選「有密碼」，路由器設 WPA2 | 相機詢問加入網路，加入後可連線 |
| S5 | Wi-Fi | 名稱含 `;`、密碼含 `:` 與 `\`（例如名稱 `Cafe;5G`、密碼 `a:b\c-2026`） | 同 S4，符號被正確還原 |
| S6 | Wi-Fi | 名稱只含十六進位字元（例如 `CAFE1234`） | 同 S4，連上的是名稱為 `CAFE1234` 的網路，名稱不含引號 |
| S7 | Wi-Fi | 路由器只開 WPA3（關閉 WPA2 相容），加密選「有密碼」 | 記錄是否能加入；不能時改寫 FAQ 說明 |
| S8 | Wi-Fi | 開放網路，加密選「無密碼」 | 相機詢問加入網路，不要求密碼 |
| S9 | 網址 | 同 S1，但改成深藍碼（`#1F3A5F`）配米白底（`#FFF8E7`） | 同 S1 |
| S10 | 文字 | 約 700 個中文字（接近上限） | 列印版在 3 公分下是否仍掃得到；掃不到時記錄可掃的最小邊長 |

## 4. 結果

待填。每一項記錄：裝置與系統版本、螢幕版結果、列印版結果、備註。任何一項失敗，先回到 #131 討論是否調整工具（例如移除 S6 的雙引號規則、改寫 FAQ 或提高對比門檻），不得只改這份紀錄。

## 5. 對產品文案的影響

- FAQ「Wi-Fi QR Code 怎麼用？」目前寫「手機會詢問要不要加入這個網路」，依 S4–S8 的結果確認或修正。
- 顏色門檻（對比至少 4.5:1，見 `app/features/tools/qr-code-generator/domain/colors.ts`）依 S9 與其他自訂顏色的結果確認或調整。
- S10 若顯示小尺寸列印的掃描下限，考慮在工具頁加上建議的最小列印尺寸。
