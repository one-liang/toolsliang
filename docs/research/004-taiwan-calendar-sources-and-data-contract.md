本研究只使用公開日曆資料，不涉及任何個人行程，也不需要任何使用者輸入。

## 2. 為什麼行事曆需要一份來源契約

一頁年曆看起來只是把日期排好，但畫面上同時出現的四種資訊來自四個完全不同的體系：

1. **西元、民國與星期**是純粹的曆法運算，長期不變，沒有「來源版本」可言。
2. **農曆日序與節氣**由天文計算決定，會隨天體攝動微調；中央氣象署自己就說未來年次需要滾動檢核。
3. **國定放假日與補假**是行政決定，由法律與行政要點決定，每年公告，而且**已公告的年度仍可能被修正**。
4. **補班日**是行政調移的結果，2025-06-13 起已從處理要點中刪除，但歷史年度仍然存在。

把這四層混成一張表，任何一層改版都會讓整頁失去可追溯性。因此本契約要求：
**每一層在每一個年度都各自帶著來源、版本、擷取日期與狀態**，缺任何一項的年度不得發布。

這也是本工具唯一能誠實主張的東西——它不保證日期正確，它保證你看得到這個日期是誰在什麼版本說的。

## 3. 資料來源

### 3.1 國定放假日與補班日

主來源是行政院人事行政總處編製、行政院核定的「政府行政機關辦公日曆表」，
在政府資料開放平臺以資料集 14718 發布：<https://data.gov.tw/dataset/14718>。

- **法律依據**：《紀念日及節日實施條例》（114 年 5 月 28 日制定公布，自公布日施行）第 4 條與第 6 條
  列舉放假的紀念日與節日，第 8 條規定「紀念日及節日之放假日逢例假日者，應予補假」，
  並把「調整放假及補行上班日期」交由目的事業主管機關調移並公告。
- **行政依據**：行政院 114 年 6 月 13 日院授人培字第 1143024631 號函修正的
  《政府機關配合紀念日與節日補假及調整放假處理要點》（原名《政府機關調整上班日期處理要點》）。
  辦公日曆表由人事總處依該要點擬訂、簽陳行政院核定，並於**每年 6 月 30 日前公告次年**；
  有特殊情形時得延後於 8 月 31 日前公告。
- **本次查核到的覆蓋範圍**：資料集宣告 `coverageStartedDate` 2017-01-01、`coverageEndedDate` 2027-12-31，
  實際檔案為民國 106 至 116 年，2026-07-15 最後更新。
- **授權**：政府資料開放授權條款第 1 版。
- **欄位**：`西元日期`（`YYYYMMDD`）、`星期`（中文單字）、`是否放假`（`0` 上班、`2` 放假）、`備註`。

同一資料集另提供「Google 行事曆專用」CSV。它是同一份決定的另一種排版（只列出有事件的日子），
資訊量較少且欄位不同，本契約不採用，避免兩份檔案在同一年度給出不同結論。

### 3.2 農曆與節氣

主來源是交通部中央氣象署逐年出版的「日曆資料表」：<https://www.cwa.gov.tw/V8/C/D/calendar_data.html>。
每年一份 PDF，網址形式為 `https://www.cwa.gov.tw/Data/astronomy/{西元年}cal.pdf`，
內含國農曆對照、節氣日期與時刻、朔望兩弦與日月食。本次查核可取得 2008 至 2028 年，2029 年尚未發布。
2026 年版的節氣表明確標示「時間為臺灣時（世界時 +8 小時）」，並註明天文資料以美國海軍天文台的
MICA 2.2.2 為參考。

117 年（2028）版在表末寫出這份契約最需要的三句話，逐字引用：

> 1. 日序與星期位序均依本表標示為準，長期可用，不會任意修改。
> 2. 農曆日序、節氣及閏月之確切時點，會依月球受太陽系各天體引力(攝動)之影響而微調，可能會影響民俗節日日期之制定。
> 3. 本表未來年次之資料，定期於每年 2 月底前滾動式檢核調整，並於網路上公布供各界使用。

同一份表也建議「提供未來 3 年滾動式跨度資料為宜」。這三句話直接決定了 §5.1 的更新時程與
§7.1 的 `astronomical-may-shift` 免責。

機器可讀版本在氣象資料開放平臺，分成兩個資料集：
`A-A0087-001` 日曆資料—國農曆對照（<https://opendata.cwa.gov.tw/dataset/astronomy/A-A0087-001>）
與 `A-A0087-003` 日曆資料—節氣日期（<https://opendata.cwa.gov.tw/dataset/astronomy/A-A0087-003>）。
官方說明檔給的欄位是：

- `A-A0087-001`：`格里曆日期`（`YYYY-MM-DD`）、`民國曆年`（`YYY`）、`農曆年`（歲次文字）、
  `農曆月`（數字 1~12，逢閏月於月數前加一個「閏」字）、`農曆日`（數字 1~30）、`星期`（1~7，7 代表星期日）。
- `A-A0087-003`：`格里曆日期`、`節氣`（非節氣點以 `-` 表示）、`節氣時分`（`hh:mm`，非節氣點以 `-` 表示），
  並註明閏秒調整可能造成節氣時間的「分」相差 1 分鐘。

這兩個資料集需要免費註冊取得授權碼；本次查核在沒有授權碼的情況下只能得到
`401 Forbidden: Authorization key is not correct.`，因此**它們宣告的年份覆蓋範圍尚未經過本次查核確認**
（§9 的未收斂問題）。授權碼屬於維運者，只在建置時使用，永遠不得出現在瀏覽器可讀的任何位置。

### 3.3 交叉核對來源

香港天文台的「公曆與農曆對照表」在 DATA.GOV.HK 發布，逐年 CSV，欄位為
公曆日期、干支年、生肖、農曆月（閏月以「閏」開頭）、農曆日：
<https://data.gov.hk/tc-data/dataset/hk-hko-rss-gregorian-lunar-calendar-conversion-table>。
本次查核可取得 2023 至 2028 年。香港時間與臺灣時間同為 UTC+8，朔與節氣的時刻換算成曆日的結果相同，
因此農曆日序可以直接比對。

本次以它逐日比對中央氣象署 2026 年日曆資料表，24 個節氣的日期與農曆日序**完全一致**；
2028 年的閏五月起訖（2028-06-23 為閏五月初一）兩邊也一致。
它是核對用的第二意見，不是權威：兩邊不一致時以中央氣象署為準，並依 §5.4 停止發布該年度。

### 3.4 授權與顯名標示

政府資料開放授權條款第 1 版（<https://data.gov.tw/license>，2015-07-27 訂定）給的是永久、
全球、非專屬、不可撤回、免授權金的重製、散布、公開傳輸與改作權利，含商業利用與再授權，
但**要求顯名標示**，且未依規定標示者「所得之授權自始失其效力」。必須標示的四項是：

1. 資料提供機關的名稱與發布年度。
2. 資料集名稱與版本。
3. 本授權條款的聲明。
4. 授權條款的連結。

DATA.GOV.HK 的使用條款（<https://data.gov.hk/en/terms-and-conditions>）同樣允許商業利用，
同樣要求清楚標示資料來源並聲明政府的智慧財產權，並以「AS IS」提供、不負錯誤責任。

因此本工具的來源標示不是禮貌，而是授權成立的條件。§7.2 把它寫成實作必須滿足的呈現規則。

## 4. 資料模型

### 4.1 資料層

| 層 | 內容 | 權威 | 是否需要版本 |
| --- | --- | --- | --- |
| `civil` | 西元日期、民國年、ISO 星期 | 曆法運算 | 否，長期不變 |
| `lunar` | 歲次、生肖、農曆月（含閏月旗標）、農曆日 | 中央氣象署 | 是 |
| `solar-term` | 節氣名稱與臺灣時時刻 | 中央氣象署 | 是 |
| `official` | 放假日、補假、調整放假、補班日與所屬紀念日／節日 | 人事行政總處 | 是 |

`civil` 沒有來源版本，因為它不會改；把它跟另外三層放在同一個「有版本」的盒子裡，
會讓「這一頁的資料是哪個版本」變成一句無法回答的話。

### 4.2 曆日

一個曆日是四層的疊加，`lunar`、`solar-term`、`official` 三層各自可以缺席：

```text
CalendarDay {
  date         : 'YYYY-MM-DD'        // 臺灣時曆日，唯一鍵
  rocYear      : number | null       // 1912-01-01 之前為 null
  isoWeekday   : 1..7                // 7 為星期日，與 A-A0087-001 的星期欄位一致
  lunar        : LunarDate | null
  solarTerm    : SolarTerm | null    // 一日最多一個節氣點
  official     : OfficialDay | null  // 缺席代表該年度官方資料尚未收錄
}

LunarDate  { sexagenaryYear: '丙午', zodiac: '馬', month: 1..12, leapMonth: boolean, day: 1..30 }
SolarTerm  { name: '清明', time: 'hh:mm' }          // 時刻為臺灣時
OfficialDay{ kind: OfficialDayKind, holidays: OfficialHolidayId[], label: string }
```

`OfficialDay.label` 保留來源備註的原文。它不是顯示用文字，也不是鍵；它存在是為了讓任何一天都能
回頭指出「這個判斷是從官方表格的哪一格來的」，並讓 §5.3 的白名單在來源改寫措辭時立刻失敗。

`holidays` 是陣列而不是單一值，因為來源真的會把兩個節日放在同一天：113 年的備註
「兒童節及民族掃墓節」就是一格兩節。用單一值就得在資料模型層做一次不可逆的取捨。

### 4.3 年度資料集

發布單位是「年度」，不是「月」。一個年度資料集長這樣：

```text
CalendarYear {
  year        : number
  rocYear     : number
  layers      : { lunar: LayerEdition, solarTerm: LayerEdition, official: LayerEdition }
  days        : CalendarDay[]        // 恰好覆蓋該年每一天一次
}

LayerEdition {
  status      : CalendarDataStatus
  datasetId   : TaiwanCalendarDatasetId
  edition     : string               // 來源自己的版本標示，例如 '114年辦公日曆表(1141020更新)'
  publishedAt : 'YYYY-MM-DD'         // 來源發布或更新日
  retrievedAt : 'YYYY-MM-DD'         // 本站擷取日
  checksum    : string               // 擷取檔案的雜湊，差異檢查用
}
```

`edition` 用來源自己的字串而不是本站自訂的流水號：使用者要能拿這個字串回到來源網站找到同一份檔案。

### 4.4 年度資料狀態

| 狀態 | 意義 | 介面呈現 | 可否索引 |
| --- | --- | --- | --- |
| `published` | 該層已依來源版本收錄 | 正常顯示，附版本與擷取日期 | 是 |
| `revised` | 來源已發布修正版並取代先前版本，本站已換版 | 正常顯示，另標示「已依 {edition} 更新」 | 是 |
| `not-announced` | 主管機關尚未公告該年度 | 該層留白並說明尚未公告，不顯示任何推測值 | 否 |
| `offline-outdated` | 裝置離線，顯示的是先前下載的版本 | 正常顯示，另標示版本可能不是最新 | 不適用（離線） |
| `conflict` | 跨來源或跨層檢查不一致 | 停止發布該年度該層，顯示暫時無法提供 | 否 |

`not-announced` 與 `conflict` 都不顯示日期，但理由不同，因此不合併：前者是「還沒有人決定」，
後者是「有人決定了但我們對不起來」。把兩者說成同一句話會讓使用者以為政府還沒公告。

一個年度只要有任一層是 `not-announced` 或 `conflict`，整年就不得進入 sitemap，也不得輸出
structured data；規格 12.5 節要求年度頁「完整、有來源版本且 canonical」才可索引。

## 5. 年度更新契約

### 5.1 更新時程

| 層 | 來源自述的節奏 | 本站檢查時機 |
| --- | --- | --- |
| `official` | 每年 6 月 30 日前公告次年；特殊情形延後至 8 月 31 日前 | 每年 6 月、9 月各一次，另每季重新擷取已收錄年度以偵測修正 |
| `lunar`、`solar-term` | 每年 2 月底前滾動檢核未來年次並公布 | 每年 3 月一次，另在 `official` 檢查時一併重新擷取 |

「每季重新擷取已收錄年度」不是保險起見：114 年的辦公日曆表在 2024 年 7 月首次發布之後，
於 2025 年 10 月被修正版取代，新增了三個放假日（§6.5）。只在年度首次發布時擷取的做法，
會讓已上線的年度靜靜地停留在錯的版本上。

### 5.2 擷取與正規化

1. **編碼不可假設。** 同一個資料集裡，114 年原始版是 UTF-8 with BOM，114 年修正版是 Big5。
   擷取必須依序嘗試 UTF-8（含 BOM）與 Big5，兩者都失敗即以 `unsupported-encoding` 中止，不得以替代字元硬解。
2. **欄位以名稱對應，不以位置對應。** 缺少任一必要欄位即 `missing-column`。
3. **日期正規化為 `YYYY-MM-DD`**，並以臺灣時解讀；`是否放假` 保留原字串比對，只接受 `0` 與 `2`。
4. **備註去除前後空白後查白名單**（§5.3）。命中才轉成日別與假日 id。
5. **節氣與農曆的 `-` 代表該日沒有值**，轉成 `null`，不轉成空字串。
6. **節氣時刻只到分**，且來源已註明閏秒可能造成 1 分鐘差異；本工具不顯示秒，也不用時刻做任何判斷，
   只用它換算出的臺灣時曆日。

### 5.3 備註標籤白名單

`備註` 欄的措辭不是穩定鍵。民國 106 至 116 年的 12 個版本裡出現 22 種寫法，其中
「兒童節及民族掃墓節」「民族掃墓節」「清明節」指同一個節日，「孔子誕辰紀念日/教師節」與
「孔子誕辰紀念日」也是，而「補行上班」「調整上班」以及「補假」「調整放假」「放假」各是同一件事的兩、三種寫法。

會讓「以後還會不會有補班」這個問題在資料層就答不出來。

### 5.4 差異檢查

每次擷取都跑完以下檢查才允許換版。任何一條不通過就停在 `conflict`，不自動修補、不自動略過。

**單一年度的結構檢查**（106–116 年 12 個版本全部通過）：

1. 該年每一天恰好出現一次，天數等於西元年的天數（平年 365、閏年 366）。
2. `是否放假` 只有 `0` 與 `2`。
3. `星期` 欄與日期實際的星期相符。
4. 每個備註都命中白名單。
5. `national-holiday`、`substitute-holiday`、`bridge-holiday` 的旗標必為 `2`；`makeup-workday` 必為 `0`。
6. 補班日只落在星期六（106–116 年共 23 筆，全部成立）。
7. 補假與調整放假只落在星期一至五。

**跨層檢查**（2024–2027 年全部通過）：

8. 民族掃墓節（清明節）的日期等於該年清明節氣的日期。
9. 春節的第一天等於農曆正月初一；農曆除夕是正月初一的前一天；小年夜是除夕的前一天。
10. 端午節等於農曆五月初五；中秋節等於農曆八月十五。

**跨版本檢查**：

11. 與已收錄版本逐日比對，列出所有 `(日期, 舊值, 新值)`。差異不為空時停在 `conflict`，
    由維運者確認來源確實改版後才換 `edition` 並改為 `revised`。
    checksum 相同即跳過比對。

**刻意不做的檢查**：不驗證補假可以由規則推導出來。以 12 個版本實測，
「逢星期六補前一個上班日、逢星期日補次一個上班日」只在 108、111、115 三個年度完全成立；
其餘年度至少有一筆例外，例如：

- 春節連假的補假被排在整段連假之後（113 年除夕 2/9 起連假到 2/12，補假落在 2/13 與 2/14）。
- 同一天有兩個節日時另補一天（114 年 4/4 是星期五、同時是兒童節與民族掃墓節，補假在 4/3）。
- 補假跨年，寫在**前一年**的檔案裡（110 年 12/31 的補假，補的是 111 年 1/1 逢星期六的開國紀念日；
  116 年 12/31 同理，補的是尚未公告的 117 年 1/1）。

因此補假一律採用官方公告。工具不重算，也不宣稱能預測。

### 5.5 擷取錯誤

擷取錯誤只有維運者會看到，出現時該年度該層停在 `conflict` 或維持前一版，不會半套上線。
表中列序即檢查順序，第一個不通過的就是回報的錯誤。

| 錯誤 key | 觸發條件 |
| --- | --- |
| `unsupported-encoding` | UTF-8 與 Big5 都無法解碼來源檔案 |
| `missing-column` | 缺少任一必要欄位 |
| `incomplete-year` | 日期有缺漏、重複，或天數與該年不符 |
| `unknown-flag` | `是否放假` 出現 `0`、`2` 以外的值 |
| `unknown-label` | 備註不在白名單內 |
| `weekday-mismatch` | 來源的星期欄與日期實際的星期不符 |
| `flag-kind-mismatch` | 日別與旗標矛盾，例如補班日的旗標是 `2` |
| `cross-layer-conflict` | §5.4 第 8 至 10 條的跨層檢查不成立 |
| `edition-changed` | 已收錄年度的內容有變動，需人工確認後才換版 |

### 5.6 檢視錯誤

檢視錯誤是使用者會看到的狀態。中英文句子可直接採用；調整語氣時必須保留同一個主張。
`{year}`、`{firstYear}`、`{lastYear}` 由實作以數字填入。

| 錯誤 key | 觸發條件 | 繁體中文 | English |
| --- | --- | --- | --- |
| `invalid-year` | 年份不是整數 | 請輸入西元年份，例如 2026。 | Enter a Gregorian year, for example 2026. |
| `year-out-of-range` | 年份超出已收錄範圍 | 目前提供 {firstYear} 至 {lastYear} 年，{year} 年不在範圍內。 | Years {firstYear} to {lastYear} are available; {year} is outside that range. |
| `year-not-announced` | 該年度的官方或天文資料尚未公告 | {year} 年的辦公日曆表主管機關尚未公告，這裡不會先猜。 | The office calendar for {year} has not been announced yet, and this page will not guess it. |
| `year-not-downloaded` | 離線且該年度未快取 | 目前離線，這台裝置還沒下載過 {year} 年的資料；連線後再開一次就會保存起來。 | You are offline and this device has not downloaded {year} yet; open it once online and it will be kept. |

檢查順序即上表列序：年份格式先於範圍，範圍先於公告狀態，公告狀態先於離線。
先說「還沒公告」再說「沒下載」，才不會讓使用者以為連上網就看得到一個根本不存在的年度。

| `2025-12-25` | `workday` | `""` | `national-holiday` | `"行憲紀念日"` |

修正版的檔案編碼是 Big5，原始版是 UTF-8 with BOM；同一個資料集內的編碼不一致，
是 §5.2 第 1 條存在的原因。

### 6.6 不變式

以下性質對每一次擷取都成立，測試逐條驗證，實作不得以特例繞過：

1. `民國年 = 西元年 − 1911`，且 1912-01-01 之前回傳 `null`，不回傳 0 或負數。
2. 每個年度資料集恰好覆蓋該年每一天一次。
3. `是否放假` 只有 `0` 與 `2`；出現其他值即為擷取失敗，不得猜測。
4. 每個備註都命中白名單；未知標籤是擷取錯誤，不得靜默忽略或當成純文字顯示。
5. `national-holiday`、`substitute-holiday`、`bridge-holiday` 的旗標為 `2`；`makeup-workday` 為 `0`。
6. 補班日只出現在星期六；補假與調整放假只出現在星期一至五。
7. 沒有備註的放假日必定是星期六或星期日；沒有備註的上班日必定是星期一至五。
8. 假日 id 只掛在 `national-holiday` 上，且每個已發布的 id 至少有一個備註寫法對應得到。
9. 民族掃墓節（清明節）的日期等於該年清明節氣的日期。
10. 春節落在農曆正月初一至初三；農曆除夕是正月初一的前一天，農曆日為廿九或三十，兩者都要有向量。
11. 節氣曆日以臺灣時判定；每一列的 `UTC 曆日` 都由臺灣時時刻減 8 小時算出，
    且與臺灣時曆日不同的列，時刻必定早於 08:00。
12. 一年恰有 24 個節氣，名稱不重複，順序自小寒至冬至。
13. 閏月與前一個同號的平月共用月數，只以 `leapMonth` 區分；農曆日不超過 30。
14. 農曆年（歲次）在正月初一換年，與西元年不同步。
15. 每一層在每一個年度都帶著狀態、資料集、版本、發布日與擷取日；缺任一項的年度不得發布。
16. 可發布年份是所有需要來源的層的覆蓋範圍交集。

### 7.2 來源標示

政府資料開放授權條款第 1 版要求顯名標示，未依規定標示者授權自始失其效力（§3.4）。
因此以下四項不是選配，中英文頁都必須具備，且必須出現在年曆本身附近，不是只在說明頁：

1. 每一層的資料提供機關名稱與發布年度。
2. 資料集名稱與本站採用的 `edition`。
3. 「本資料依政府資料開放授權條款第 1 版提供」的聲明；香港天文台的資料另依 DATA.GOV.HK 使用條款標示。
4. 授權條款的可點擊連結，以及資料集本身的可點擊連結。

另外必須顯示資料契約版本識別碼 `taiwan-calendar-2026-09-06` 與本站擷取日期。
任一來源改版或本契約的規則改變時，必須重新查核、更新識別碼與 `reviewedAt`，
並同步本文件與測試。工具 slug `taiwan-calendar` 不隨之改變。

### 7.3 禁止用語

不得出現：政府日曆、官方行事曆 App、國定假日查詢保證、最新假期公告、勞工行事曆、學校行事曆，
以及 official government calendar、guaranteed holiday list、authoritative holiday API 等對應說法。
不得暗示本站是主管機關的公告管道、不得宣稱能提前得知尚未公告的假期，
也不得把政府行政機關的辦公日曆表說成勞工或學生的出勤依據。
年度頁面標題使用永久寫法（例如「台灣行事曆」），不使用「2026 行事曆」這類會過期的名稱，
與 CONTEXT.md 的用語規則一致。

## 9. 已收斂與未收斂的問題

- **要不要自己算農曆與節氣？** 不要。自算會讓本工具變成另一個天文計算的權威來源，
  而使用者無從驗證；改以中央氣象署的公布值烘焙成靜態資產，並保留來源版本。
- **要不要在執行期呼叫任何來源 API？** 不要。ADR-0001 要求工具內容留在裝置，
  而年份與篩選一旦送出就會離開裝置；全部資料在建置時烘焙，執行期零請求。
- **要不要支援 1912 年起的所有年份？** 不要。可發布年份是兩個來源層的交集，本次為 2017–2027。
  超出範圍以 `year-out-of-range` 說明，不以推算補足。
- **要不要顯示朔望與日月食？** 第一版不做。來源有資料，但它們與「放假、補班、農曆、節氣」不同用途，
  會讓年度頁的資訊密度失控；留待另開 ticket。
- **未收斂：氣象資料開放平臺兩個資料集的年份覆蓋範圍。** 需要免費授權碼才能查詢，
  本次查核以無授權碼取得 `401`，因此只能確認日曆資料表 PDF 的 2008–2028。
  T14 取得授權碼後必須補查，若機器可讀通道的覆蓋較窄，`cwa-calendar-table` 的覆蓋範圍必須跟著縮小。

## 10. 已知風險

1. **已公告的年度會被修正，而使用者不會回頭重看。** 114 年在年中新增三個放假日就是實例。
   因此已收錄年度必須定期重新擷取（§5.1），介面必須顯示 `edition`，
   且 `edition-may-change` 免責必須恆常呈現，不能只在說明頁出現。
2. **補假無法由規則推導，例外每年不同。** §5.4 已證明三種例外（連假後補、一日兩節日、跨年補假）。
   任何「幫使用者算下一年會怎麼放」的功能都會在某一年給出錯的答案，第一版不做，
   也不在文案裡暗示本工具知道未公告年度的安排。
3. **來源的檔案格式沒有承諾。** 同一個資料集內編碼不一致（UTF-8 with BOM 與 Big5），
   備註措辭 12 個版本出現 22 種寫法，下載網址帶著會變動的檔案 UUID。
   因此擷取必須靠白名單與結構檢查，任何未知值都要中止而不是猜測；
   網址失效時 §5.5 的 `missing-column` 之前就會失敗，不會發布半套資料。
