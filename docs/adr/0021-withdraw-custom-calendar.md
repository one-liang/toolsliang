# 下架自訂行事曆

依使用者要求（#89），下架自訂行事曆工具。它不再出現在工具目錄、首頁、搜尋、sitemap、結構化資料、FAQ、安裝捷徑與離線殼層快取，工作區、項目編輯表單與自訂行事曆文件格式的程式一併移除。`custom-calendar` 這個 slug 依 ADR-0011 保留，以未發布狀態留在工具註冊表，避免日後被其他工具佔用；已加入常用工具的裝置會依註冊表自動略過這筆收藏，不會留下點不開的項目。台灣行事曆不受影響。

舊網址不回 404。曾經公開的工具頁仍留在書籤與搜尋結果裡，所以兩個語系的 `/{locale}/tools/custom-calendar/` 都以 301 永久轉到同語系的台灣行事曆：它是自訂行事曆原本疊加的官方基線，也是最接近的替代。轉址目標記在註冊表那一筆紀錄的 `redirectTo`，由 Nitro route rule 在伺服器回應。Cloudflare Workers 部署（ADR-0005）刻意不預先產生這些路徑：預先產生的檔案會由 Static Assets 以 200 搶先送出，蓋掉 Worker 的 301。GitHub Pages demo（ADR-0018）沒有伺服器，改在建置時把每個舊網址寫成一載入就轉向的頁面。

不為自訂行事曆另外提供匯出或轉換。裝置上已保存的自訂行事曆仍是 ADR-0007 的本機資產：資料庫保留 `calendar` 這個資產種類，讓舊紀錄照常讀得出來，在本機資產頁（`/{locale}/storage/`）標示為「自訂行事曆（已下架）」，可以檢視名稱、大小與更新時間，也可以刪除；讀不到或由較新版本寫入的紀錄同樣可以刪除。本機資產頁原有的整體備份照舊涵蓋裝置上的全部資產，因此也包含這些舊紀錄。不再有任何工具會寫入新的自訂行事曆，ADR-0007 列舉的可保存資產從此不含自訂行事曆。

若日後要恢復，需重新評估它和台灣行事曆的分工，補回工作區、FAQ 與 e2e 驗證，並移除這筆轉址。
